# Study Notes Formatter

This skill is the repo's format. Every rule for note files, `_vocabulary.md` / `_expressions.md`, the
indexes and the topic pages lives here: in this file, `references/topics.md` and `scripts/notes.py`.
When a convention changes, change it here.

`notes.py` below means `python3 .claude/skills/study-notes-formatter/scripts/notes.py`, run from the
repo root.

The input is an analysis of a Korean text, pasted or written earlier in the conversation. File what
the analysis says; don't analyse the Korean again. The one judgement you add is whether each point
fits the TTMIK lesson it names — when something doesn't fit, stop and ask.

## The repo

```
level-N/<grammar>.md           one note file per TTMIK lesson's form; examples grouped by source
_vocabulary.md                 vocabulary, one ## section per source
_expressions.md                useful expressions, one ## section per source
README.md, level-N/README.md   generated by `notes.py index`; never edit by hand
topics/                        cross-level topic pages (references/topics.md)
skills/korean-grammar-extractor/references/ttmik-grammar-map.md   the TTMIK lesson table
```

## A note file is a TTMIK lesson

A note file stands for one lesson's form. Its identity is the first lesson on its
`> TTMIK Level X Lesson Y` line — not its filename, and not how a form happens to be spelled. Whether
two things are "the same grammar" is decided by what TTMIK teaches (the lesson table and its
子形态核对), never by matching text:

- Same lesson → same file, however the analysis spells the form. L4-8 lives in `-아어도-돼요.md`;
  an analysis headed `-아/어/여도 되다 — TTMIK Level 4 Lesson 8` goes there.
- Different lessons → different files, however alike the forms look: -(이)라고 (L5-10) and
  -(이)라는 + N (L5-12) are two files.
- An example belongs to the lesson whose form it actually contains. A sentence that says the same
  thing with other grammar (-고 그 이후에 for -(으)ㄴ 후에) is not an example of that lesson.

## Filing an analysis

1. **Sync.** `git pull`, so create-vs-append is decided against the real repo.
2. **Read the analysis.** Take the H1 (the source title, which names the `##` section in every file
   it reaches) and its `> 来源：` line; each `## <form> — TTMIK …` point with its `> 📖 语法核心：` line
   and `### 例句` blocks; the 词汇积累 and 好用的表达 tables. Everything else stays in the chat: 大意,
   本文语法一览, the teaching notes under each point (形态, 意思与语感, 中文对照, 和学过的课), 自测.
   No source title in the analysis: ask for one.
3. **Route each point** by the first lesson in its header.
   - `notes.py lookup L8-4` prints the file holding that lesson (or `none` and a
     suggested name), the lesson-table row and its 子形态核对 entries.
   - File found → append to it. None → create one in `level-X/` (naming below).
   - 「TTMIK 未单独成课（最接近：Level X Lesson Y）」 → the closest lesson's file, with a 讲解 that says
     the form has no lesson of its own. No closest lesson → a row in the source's `_expressions.md`
     table.
   - 「课号待核实」 → don't file it; name it in the report.
   - The header's lesson doesn't match the lesson table (子形态核对 puts the form in another lesson,
     or the row teaches something else) → don't file it; ask.
4. **Write.**
   - New file:
     ```
     # <form> — <short Chinese gloss>

     > TTMIK Level X Lesson Y
     > 📖 语法核心：<from the analysis>

     ## <source title>

     > 来源：<from the analysis>

     ### 例句 1
     **原句：** …
     **场景：** …
     **拆解：**
     - …
     **讲解：** …
     ```
     A point with several lessons lists them all in the analysis's order:
     `> TTMIK Level 7 Lesson 18 · Level 10 Lesson 12`.
   - Existing file: leave its H1 and header lines alone; append `---` and the `## <source title>`
     section. If the source already has a section in that file, ask whether to replace or skip it.
   - Copy the example blocks as written, numbered from 1 inside each source section.
   - `_vocabulary.md` (`| 단어 | 词性 | 意思 | 备注 |`) and `_expressions.md`
     (`| 表达 | 意思 | 用法说明 |`): append a `## <source title>` section with the analysis's table; if
     the source already has one, add only the rows it lacks.
   - No calendar dates anywhere; the git log is the chronology. Keep source attribution, and drop any
     date that came in with the analysis.
5. **Indexes and checks.** `notes.py index`, then `notes.py check`,
   and fix whatever it reports. It checks that every note's lessons exist and its folder matches,
   one file per lesson, no dates, every link resolves to the path git stores (a link spelled in
   decomposed Hangul works on a Mac but 404s on GitHub), indexes current, and topic-page links and
   quoted fragments still true.
6. **Topic pages.** `notes.py topics <the lessons you touched>` lists their labelled
   cells; update them as `references/topics.md` says.
7. **Commit and push** — one commit per filed source, its notes, indexes and topic pages together:
   `Add Level 5 notes from <source>`, or `Add L3/L4/L5 notes from <source>` across levels. Other
   changes get a plain description (`Rebuild indexes`, `Refile examples by lesson`). Push the current
   branch.
8. **Report** in a few lines: files created and appended to (examples added to each), points held
   back and why, topic labels changed. Don't reprint the notes.

## Naming a new file

Name it after the form TTMIK teaches (the lesson table's pattern, not a conjugated form from the
text), Korean kept as-is: drop `/`, spell out `~`, spaces become `-`. `-거든요.md`, `-(으)니까.md`,
`-아/어 주다` → `-아어-주다.md`, `전혀.md`.

## Editing by hand

Fixing a typo, moving a misfiled example, splitting a file: the same rules apply. An example moves
to the lesson whose form it shows, and a note file left without examples is deleted. Then
`notes.py index`, `notes.py check`, the topic labels, one commit.
